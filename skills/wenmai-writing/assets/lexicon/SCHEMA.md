# 表达库编写规范（v1）

一行一个 JSON 对象，UTF-8 JSONL。每条是一个独立表达，不以同一词搭配不同宾语重复计数。常规词语、成语、四字搭配和表达框架分别标识；不要求罕见词或成语比例。

必需字段：
- `id`：research 为 r、analysis 为 a、commentary 为 c、literary 为 l，前缀后为四位编号，从 0001 开始。删除条目后允许编号不连续。
- `expression`：可独立检索的词或表达，唯一。
- `kind`：书面词 / 成语 / 四字搭配 / 表达框架。
- `function`：具体写作任务。
- `meaning`：简明准确的中文释义，不夸大证据强度。
- `collocations`：1—3 个自然搭配或填入方式的字符串数组。
- `genres`：从 技术报告 / 学术综述 / 评论 / 散文 / 叙事 中选择的非空数组。
- `example`：原创用法示例，不引用外文、不虚构真实研究或作者亲历。示例只是说明用法。
- `avoid`：针对本词的误用边界，不能整库重复同一句泛泛提示。
- `provenance`：固定为 `editorial`。这意味着通用词汇与原创编写的释义、搭配和例句；不声称来自某篇文章或经过词典逐条核证。

条目本身是编辑候选，不是高分模板。先理解原句，再检索、择用。不得将库容量解释为文采或检测有效性。确需注明文章中某个词的用法时，应另存可回到具体段落的来源证据，不混入本库的原创例句。

`kind`是编辑检索标签，不是全库已通过辞书分类核证的声明。固定四字表达的成语分类存疑时，可以保守标为四字搭配并在`avoid`说明；不得据此断言它不属于成语。明确词条分类后可更正，记录实际核查范围。
