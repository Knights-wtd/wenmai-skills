# 文脉：独立督查

## 任务与独立性

接受原稿、候选稿、用户约束和可核查的参考材料，独立判断是否改善了表达。先形成自己的判断，再阅读编辑者的理由；不要把编辑者“已经审查”的声明当成证据。

用户授权独立督查、子代理或并行审查，且当前工具支持时，派出独立审查代理。没有该授权时，先遵守所在环境的代理规则。第二会话可使用下方交接材料，不能假称已经派出代理。工具不支持独立会话时可自行复核，交付中注明是同一会话复核，不冒称独立审查。

上述委派由组织编辑流程的会话执行。已经被派出的督查者直接完成指定审查，不因本技能再递归委派其他代理。

督查属于编辑流程，不是额外的发布许可。已获授权的修正、复核与交付继续完成；只有缺少必要信息或涉及新的未授权操作时才询问用户。

## 交接材料

给督查者：原稿、候选、修改范围、文体、用户认可的风格示例、保护项、实际阅读材料及读取范围。初审阶段不提供编辑者的自评分与辩护理由，不要求督查者“证明改写更好”。

可直接采用的任务说明：

```text
请独立审查原稿与候选。先逐句比较含义，再检查表达。
保留数字、公式、引用、限制条件、否定、比较前提与研究阶段。
指出具体位置、原句、候选句、问题和可行修正。
核对所用词的含义、搭配、文体及来源中的实际作用。
没有明确改善时可以建议保留原句；不要为交差强行换词。
先形成判断，再查看编辑说明。不预测检测分数。
审查整个指定范围；抽查或缺少原文须明确说明覆盖限制。
```

## 核查顺序

### 1. 原意与证据

逐句检查：新增或遗漏了什么；主语、对象、条件、时序、否定是否改变；可能性是否变成确定性；相关是否变成因果；计划是否写成已完成；结论依据是否被误写成结论适用范围。

强断言需要原稿已有的证据支持。发现含义变化时优先修正，不能以文采抵偿。

### 2. 措辞与句间关系

检查词义、感情色彩、搭配对象、施事与承受对象。四字表达不自动是成语；书面词不自动优于普通词。文学意象须对应已有材料，不替代技术解释。

长句检查层次、修饰归属与比较前提；短句检查是否留下缺失的因果、指代或条件。阅读全文及相邻段，防止同一个句式或判断反复出现。

逐条检查本轮实际选用的素材，而非把词库中的标签当作使用正确的证明。需要时读素材的释义、搭配、例句及误用边界。

### 3. 阅读与出处

要求可回到具体正文位置，检查摘词是否真的出现、原文作用是否理解正确、迁用是否仍合适。只读节选就记录节选；网页不可获取时保留待核查状态。阅读目录不等于当前已重新取得全文。

通用词库中的 `editorial` 条目是编辑整理的释义和原创例句，不是媒体原句，不宣称逐条通过权威词典核证。若发现词义存疑，查证后更正或撤出，不把存疑项作为推荐候选。

### 4. 修改是否必要

指出候选具体改善了准确、清楚、承接、节奏或用户偏好的哪一项。仅“更高级”“更少见”“更像人”不是充分理由。原句已自然且准确时允许保留。

## 反馈、修正与复核

使用 `assets/review-record.template.json` 记录指定范围、实际覆盖、问题及处理。每项至少含位置、证据、问题、建议、处理和复核状态。不提供无依据的质量分或风险概率。

编辑者处理问题后，将修正内容及必要上下文交给督查者复核。复核检查是否解决原问题、是否引入新问题；已知问题不能未经处理便标记通过。

结果采用“可交付”“需修正”“待补材料”，并列出实际限制。这些状态表示指定范围内的编辑判断，不保证用户审美一致或检测通过。

## 表达库审查

新增库先做格式和精确去重，再逐条审查词义、搭配、例句、文体和误用边界。近义词可以分别收录，但必须体现不同含义或用法；同词换宾语不能另算素材。

记录逐条覆盖的 ID。全库核读、来源抽查、自动校验分别报告，不能把抽样说成逐条阅读或把自动校验说成语义审查。问题修正后复核受影响条目；删除疑似凑数项后重新计数。

## 交付

给出可用稿件或素材、关键问题与修正、实际审查范围及未解决限制。用户只要求分析时不改稿。基准与候选分别保存，检测状态另行记录。

独立审查用于尽早发现错误并减少返工。审美偏好仍应从用户的具体示例中学习；来源缺失与主观偏好不能被一次督查消除。
